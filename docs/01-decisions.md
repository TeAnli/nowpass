# 技术选型台账

每条决策都记录：结论、决定性理由、被否决的选项。**本文件是后续所有实现的依据**，改动需同步修订本文件。

## 1. 范围

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 定位 | 少数人自用、需登录的刷题站，复杂度优先让步 | 不做多租户、高并发、内容审核 |
| 2 | 功能范围 | 题库浏览（分类/难度/标签/关键词筛选）+ 点开看标准答案 + 注册/登录/找回密码 + 后台管理 | 最小可用闭环 |
| 3 | 不做的功能 | 代码评测（沙箱/Judge）、社区问答、AI 客服、刷题进度与错题本 | 沙箱是最大复杂度来源；后三者对"少数人刷题"无收益 |

## 2. 架构

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 4 | 架构分层 | 四模块（common/framework/system/admin）+ RBAC 三表 + 权限点字符串 + 操作日志；不做菜单表动态路由、字典、数据权限、定时任务、代码生成器 | 多模块让依赖方向由编译器保证；菜单表与数据权限都依赖组织树，本站不存在这种结构 |
| 5 | 模块与依赖 | `common <- system <- framework <- admin` 严格单向 | `common` 不反向依赖，依赖方向受编译器约束 |
| 6 | 前后端形态 | 前后端分离开发，生产由 Spring Boot 内嵌静态资源同源提供 SPA | 同源免 CORS / cookie 策略；前端单独目录便于独立构建 |
| 7 | 管理端与用户端 | 同一个 SPA，按 `/admin/**` 路由前缀切换 Layout，一套登录与请求封装 | 满足"两端同一项目"，权限点决定后台菜单可见性 |

## 3. 后端技术

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 8 | 基线版本 | JDK 21 / Kotlin 2.3.21 / Spring Boot 3.5.16 / Gradle 8.14.4 | Kotlin 2.3.21 是 Exposed 1.6.0 的编译下限；Gradle 8.x 是 Boot 3.5 官方支持区间；Boot 3.5.16 为 3.5.x 最后一个 OSS 补丁（OSS 支持已于 2026-06-30 结束，见"已知取舍"） |
| 9 | ORM | **JetBrains Exposed 1.6.0（DSL，非 DAO）** | 见下方专节 |
| 10 | 数据库 | PostgreSQL 16，`bigserial` 主键，`deleted boolean` 逻辑删除，`options jsonb` + `tags text[]` | 用 PG 原生类型替代多对多关联表与选项表，减少 join |
| 11 | 迁移 | Flyway（`flyway-core` + `flyway-database-postgresql`），禁用 Exposed 自动建表 | 表结构版本化，Exposed 只读不写 DDL |
| 12 | 鉴权 | **有状态 token**：UUID 存 Redis，`Authorization: Bearer <uuid>`，2h 有效期 + 剩余 <1h 滑动续期，允许多端 | 可即时撤销、可做在线用户与强退；无状态 JWT 无法做到"立刻踢下线" |
| 13 | 注册 | 开放注册，但需**邮箱验证码**证明邮箱归属，且状态为 `pending`，管理员审批后才 `active` | 与"必须登录才能看题"的目标一致，避免登录形同虚设 |
| 14 | 验证码 | 图形算术验证码（hutool-captcha），登录 / 注册 / 找回三处固定出现，Redis 存 2 分钟一次性 | `easy-captcha` 停更于 2019、`kaptcha` 停更于 2015 且为 javax 时代 |
| 15 | 限流与锁定 | 仅敏感端点（登录/注册/发码/找回）按 IP + 账号双维度限流（Redis Lua）；同账号连错 5 次锁 15 分钟 | 全局限流会误伤正常列表翻页 |
| 16 | 找回密码 | 邮箱验证码（6 位，5 分钟一次性）+ 改密后清空该用户全部 token | 不做 `reset_token` 二次跳转，少一步状态机 |
| 17 | 邮件 | `spring-boot-starter-mail`，`nowpass.mail.enabled` 可插拔；关闭时降级为"写日志 + 提示联系管理员"；开发用 Mailpit | 生产 SMTP 凭据未定，先保证链路可跑 |
| 18 | 接口文档 | springdoc-openapi 2.10.0（Boot 3.x 对应 2.x） | 接口联调与验收需要可视化文档 |
| 19 | 测试 | 关键 service 少量单测（密码/鉴权、限流窗口、筛选拼装、验证码过期），不引 Testcontainers/CI | 自用站点，投入产出比不足 |

## 4. ORM 选型专节（为什么是 Exposed）

候选：Spring Data JPA、MyBatis-Plus、Exposed、Ktorm、Jimmer、jOOQ。

| 候选 | 否决 / 采纳理由 |
|---|---|
| MyBatis-Plus | 需要为 `jsonb` 自写 `JacksonTypeHandler`、为 `text[]` 手写 `BaseTypeHandler`；本项目的两列 PG 专有类型恰好是它最难受的地方 |
| Spring Data JPA | `jsonb`/数组原生支持良好、Repository 免写 CRUD；但 Hibernate 会话/脏检查对 6 张平表属纯开销，且实体不能是 `data class` |
| Ktorm | 单人维护，2024-09 → 2026-05 停更约 20 个月；PG 专有类型需自行扩展 `SqlType` |
| Jimmer | 未到 1.0（0.9.x）；核心价值是复杂对象图的 N+1 与 DTO 语言，本站是 6 张平表，用不上 |
| jOOQ | 需构建期连库代码生成，为 6 张表搭流水线不划算 |
| **Exposed** | JetBrains 官方维护、1.x 发版正常、有 CVE 响应；`jsonb<T>()` 与 `array<String>()` 均为内置；DSL 显式可控。**代价**：无 Repository 自动 CRUD、审计字段与逻辑删除需自己封装、Spring 事务需显式配置 |

## 5. 已知取舍（必须知情）

1. **Spring Boot 3.5.x 的 OSS 支持已于 2026-06-30 结束**，3.5.16 是最后一个开源补丁，不会再有 CVE 修复。选择它的原因是 Boot 4 会连带 Jackson 3、springdoc 3.x、`exposed-spring-boot4-starter` 等一整套未验证面，交付风险更高。升级路径见 `05-development.md`。
2. **Exposed 1.6.0 的 Spring 集成在 Boot 4 时代会被移除**（官方仅提供 `spring-boot4-starter` 作为后续方向），届时需迁移。
3. **PostgreSQL 原生 identity 列**（`GENERATED BY DEFAULT AS IDENTITY`）Exposed 无官方 DSL，本项目管理用 `bigserial`。
4. **kotlinx-serialization 需显式钉 1.11.0**：Spring Boot BOM 会降到 1.6.3，与 `exposed-json` 1.6.0 的期望不符。
